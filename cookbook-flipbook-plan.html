1. Verdict

Is it possible?

Yes. The reference UI is a well-solved pattern: HTML (or canvas) pages inside a page-flip engine that simulates paper curl, shadows, and drag/click turns. You do not need custom WebGL physics. The realistic path for Plated is StPageFlip via react-pageflip (or the underlying page-flip package), mounted as a client-only component in the Next.js App Router — same class of effect as the screenshot.

Fit with today

Cookbook is currently a card grid + full form editor ((app/app/recipes/page.tsx, RecipeEditor). Specs ((RECIPE_SYSTEM_SPEC, PRODUCT_SPEC §7) describe grid/list → detail/edit, not a physical book. A flipbook is a new browse/read surface, not a replacement for editing. Keep the editor; add a “read as book” (or collection → book) mode.

2. Context & constraints

What already exists

  • Cookbook home: hero + mock collections + searchable recipe card grid
  • Detail routes render RecipeEditor (create/edit), not a reading layout
  • No Framer Motion / Three.js / page-flip libs in package.json
  • Design language: paper cream, tomato accent, Cormorant + DM Sans — maps well to “printed page” content

Hard constraints

  • Next.js 15 App Router + React 19 — flip library must be client-only (dynamic(..., { ssr: false }) or "use client" with no SSR DOM access)
  • Mobile — book must degrade to single-page portrait flips; AppShell bottom nav competes for vertical space
  • Accessibility — prefers-reduced-motion → instant page changes or fall back to list/grid; keyboard prev/next; don’t trap focus inside flipped canvases
  • Editability — don’t put the full editor inside flipping pages; link out (“Edit recipe”) to existing routes
  • Performance — don’t mount 200 full recipe DOMs at once; virtualize or build pages lazily / by collection

3. Approach comparison

Recommended · closest to reference

A. StPageFlip / react-pageflip

  • + Realistic curl, shadows, corner drag
  • + HTML pages → real text, images, links
  • + Landscape + portrait modes built-in
  • + Hard cover + soft inner pages
  • − Older React wrapper; needs careful refs / dynamic import
  • − Awkward with frequently changing children (need update APIs)
  • − Touch + nested scroll needs tuning

Best when: you want the screenshot look with recipe HTML inside pages.

DIY · lighter weight

B. CSS 3D page turn

  • + No dependency; full control
  • + Easy reduced-motion fallback
  • − Curl physics look flat vs reference
  • − Weeks to match StPageFlip quality
  • − Drag-from-corner is non-trivial

Best when: you only want a stylized half-turn, not catalog-grade realism.

Overkill for recipes

C. Three.js / WebGL book

  • + Maximum visual fidelity
  • − Heavy bundle; text/selectivity hard
  • − Editing/links/a11y painful
  • − Wrong tool for recipe content

Best when: marketing hero only — not the real cookbook.

Skip for this product

Pure image/PDF flipbooks (render each page to a bitmap) look great but kill text selection, deep links, and “Edit” CTAs. Plated recipes are structured HTML data — keep pages as DOM.

5. Architecture

Page model (suggested)

type BookPage =
  | { kind: "cover"; title: string; subtitle?: string; imageUrl?: string }
  | { kind: "toc"; entries: { title: string; pageIndex: number }[] }
  | { kind: "recipe-hero"; recipeId: string; title: string; imageUrl?: string; meta: RecipeMeta }
  | { kind: "recipe-body"; recipeId: string; ingredients: Ingredient[]; steps: Step[] }
  | { kind: "recipe-notes"; recipeId: string; notes: string }
  | { kind: "blank" };

6. Implementation plan

Phase 0 · Spike (½–1 day)

Prove the effect in-app

  • Install react-pageflip (pulls StPageFlip / page-flip)
  • Throwaway route or story with 6 static HTML pages + hard cover
  • Validate: drag flip, buttons, mobile portrait, AppShell chrome collision
  • Kill criteria: if React 19 / SSR friction is too high, fall back to raw page-flip on a ref
Phase 1 · Page system (1–2 days)

Design the paper pages

  • Build Cover / TOC / Recipe hero / Ingredients+steps page components in Plated tokens (paper bg, editorial type)
  • Implement paginateRecipes() with simple rules (hero left, body right; overflow → extra pages)
  • Pad with blank pages so the book closes cleanly; mark first/last as hard covers
Phase 2 · Wire real data (1 day)

Connect to cookbook recipes

  • Server page loads owner cookbook recipes (+ ingredients/tasks as needed)
  • “Open as book” CTA from /app/recipes
  • Page indicator, keyboard ←/→, click edges, Escape to close
  • Deep link: ?page= or ?recipe= → turnToPage
Phase 3 · Product polish (1–2 days)

Make it feel intentional

  • Collection-scoped books once collections are real (today they’re mock)
  • prefers-reduced-motion: disable animation / offer list fallback
  • Cap book size (e.g. first N recipes or active filter/collection only)
  • Optional soft ambient shadow under the open spread (CSS, not WebGL)
  • Don’t block “Edit” / import flows — book is additive
Phase 4 · Optional later

Nice-to-haves

  • Search inside book → jump to page
  • Party menu as a mini event booklet
  • Print stylesheet that dumps pages linearly

7. Risks & mitigations

Library / React 19 friction

Wrapper may be stale. Mitigate with dynamic(ssr:false), or use page-flip directly on a DOM ref.

Long recipes / many recipes

Pagination + collection scope. Avoid rendering entire cookbook DOM at once if >~40 recipes.

Touch vs scroll

StPageFlip has mobileScrollSupport; keep page content short enough that inner scroll is rare.

A11y / SEO

Book is a progressive enhancement of browsing; keep grid + editor as primary accessible paths.

8. Open questions (decide before building past the spike)

  • Is the book the default cookbook view, or an optional mode?

    Recommendation: optional (“Open as book”) so search/filter stay first-class.

  • Does a book contain all recipes, or one collection at a time?

    Collection-at-a-time scales better and matches the “physical cookbook” metaphor.

  • Fullscreen overlay vs dedicated route?

    Dedicated /app/recipes/book is simpler for SSR fetch + shareable URLs; overlay feels more magical.

  • Should party recipes get the same treatment?

    Defer — prove it on global cookbook first.

Out of scope for v1

  • Editing ingredients/steps inside flipping pages
  • True 3D WebGL book mesh
  • PDF export that preserves curl animation
  • Replacing RecipeEditor
